# Goal: backfill current configuration fields in initialized projects

- Target: ordinary root lifecycle handling compares existing project configuration with current bundled defaults and adds missing fields before readiness, without reinitializing projects or overriding explicit settings.
- Change: `scripts/evaluation-config.py --update` reuses strict parsing and recursive default resolution. It only updates an existing valid configuration when fields are missing; complete files keep bytes/mtime and absent files remain absent. Replacement stages beside the original, copies permissions before writing (including Windows ACL), flushes content, checks original identity/bytes, atomically replaces the target and removes its own staging file. Invalid/unsafe targets, permission failures, Windows read-only files requiring changes and detected concurrent edits fail without replacing the original.
- Routing: root hooks emit a concrete updater argv for the model to execute with its actual Python interpreter after selecting the ordinary-task route and before runtime readiness. The hook itself remains read-only; installation onboarding retains priority, pending/declined onboarding never runs the updater and delegated roles receive no updater. Default resolver/evaluation calls remain read-only. Canonical policy, setup/orchestrator/evaluation guidance and human configuration/architecture/onboarding docs distinguish these responsibilities.
