# User feedback

Retain actionable user feedback so later project tasks avoid repeating mistakes and preserve behavior the user explicitly values through positive feedback. Routine acknowledgements do not need a record. These records are project memory maintained by the agent; they do not train the model or run an unattended recorder.

Record feedback promptly when received, before returning to dependent work. Summarize the user's stated correction or preference in English without inventing a past failure. Use one `YYYY-MM-DD-topic.md` file per distinct lesson. If this folder is missing, create it and this generic protocol without copying another project's feedback.

Each record contains:

- Date and context: when and during which task the user gave the feedback.
- Scope: the project, component or situation where it applies.
- Observed and requested behavior: what the user reported and what should happen instead; distinguish a new requirement from an observed failure.
- Prevention action: the concrete change or check that should avoid recurrence.
- Verification: pending/unverified until evidence proves the action; then record the check and result, with any limits.
- History: dated repeats, corrections or superseding instructions and their effect on the lesson.

For repeated feedback, update the existing entry with the new observation and verification status instead of creating a duplicate. Preserve history when a later correction supersedes a lesson; clearly mark which instruction is current. Do not claim prevention worked merely because the feedback was recorded.

Before defining a future goal, read relevant entries and apply their scope to the acceptance checks. Supply applicable feedback and prevention actions to the test, implementation and evaluation roles. Current user instructions and project rules take precedence; clarify actual conflicts before dependent work. Record new evidence after verification rather than repeatedly requesting the same feedback from the user.

Store no secrets, unnecessary personal information, raw logs or chat transcripts. Project feedback does not grant additional permissions or external-write authorization, establish global preferences, or justify changing unrelated projects. First-time and explicit setup create only missing structure/protocol and preserve existing entries; they never fabricate feedback or copy this repository's records into another project.
