# Goal: complete marketplace plugin and lifecycle setup

- What: Removed standalone installers. Bundled all stack skills, six Ponytail skills with real hooks, Caveman, and UIUX search/data in the plugin. Added a dedicated repository marketplace, setup onboarding, and root/sub-agent lifecycle adapter.
- Why: User decision: an installable Codex plugin with normal one-time hook approval; setup/readiness before the original request, separate TDD roles, no recursion in sub-agents.
- Locations: `.agents/plugins/marketplace.json`, `.codex-plugin/plugin.json`, `hooks/`, `skills/`, `scripts/setup-runtime.py`, `assets/versions.json`, `assets/bundle-manifest.json`, `docs/adr/0002-codex-marketplace-und-lifecycle.md`.
- Host finding: Portable root manifests produced no hooks in CLI 0.159.0. Native Codex configuration with a minimal root identity was discovered in isolation as twelve skills, six untrusted plugin hooks, and setup onboarding; no trust approval was performed. Details are in the ADR.
- Runtime: Checks are read-only by default; repair writes marker-managed rules, preserves unrelated content, and blocks damaged markers/MCP conflicts. The CodeGraph npm pin and observed runtime version remain separate. RTK repair verifies official release SHA256 before installation.
- TDD: The test agent first demonstrated 14 failures and five passes. The evaluator found reversed markers; the test agent added RED, and the implementer corrected the order check. Subsequently, 29 regression tests and the PowerShell configuration test passed. Both owned skills were validated and hook syntax checked.
- Readiness: The running default check reported all 13 runtime checks successful and `runtime_ready=true`; `ready=false/session_verification_required=true` remain intentionally set. An actual CodeGraph MCP status call in the implementation session succeeded. Final independent verification remains the evaluation agent's role.
- Limits: No complete tool installation from scratch on all platforms, no hook execution after user trust, and no plugin installation in the real main profile. Two earlier loose local skill entrypoints are compatibility pointers to the current repository skills; remaining files were retained. No external publication.
