# Container authentication onboarding

- Scope: user-assisted graphical onboarding of a fresh AMD64 test container from PR revision `cb9b0c1`; Docker runs AMD64 under emulation on Apple Silicon.
- Baseline: no login cache, six untrusted KISS hooks, no hook errors; separate localhost SSH target and fresh named volumes.
- Finding: the user reported that the standard browser redirect failed again. The profile does not forward the remote callback on port 1455, so the host browser cannot reach that listener through its own localhost.
- Change: make device authentication the initial documented sign-in step, before connecting the desktop project. Preserve the existing network boundary and normal hook trust.
- Authentication evidence: ran the documented container-only `codex login --device-auth`; the user completed the official browser authorization. The command reported success, `codex login status` confirmed ChatGPT sign-in and a fresh SSH App Server returned an authenticated account. No credentials were copied from the host or recorded here.
- Initial pause: all six KISS hooks reported untrusted on the first readback. Desktop reconnection, graphical hook review and model-driven setup required user action because Computer Use refuses access to the Codex application.
- Completed user-assisted onboarding: the tester connected the remote desktop project at `/work`, explicitly supplied that path to the setup skill, reconnected the host and approved the KISS hooks in the UI. A fresh `hooks/list` returned all six as trusted, without hook errors. The remote desktop chat then completed a real `codegraph_status` MCP call for `/work` and created the final project configuration exclusively after readiness succeeded. Its tool-call completion and configuration-write results were independently inspected. The resolver validated `plan-mode=false` with both evaluation switches enabled; no SonarQube service was provisioned.
- Additional functional proof: indexed a uniquely named temporary Python file through the installed CodeGraph CLI, then successfully searched its symbol and traced its two-function call path through actual MCP calls. Removed only that owned file and synchronized the index afterward.
- Persistence: after restarting only this test container, the account remained authenticated, all six hooks remained trusted, runtime readiness passed and CodeGraph MCP responded. The final configuration was preserved. The service remains available for the tester; its named volumes were retained.
- Limits: GUI actions were performed by the tester rather than automated; individual SubagentStart hooks did not receive a separate event-execution test. Native x86 hardware, Windows and the upstream Sonar gate remain unverified.
- Verification: documentation-only publication; relative links and whitespace checked. Runtime source, network settings, tests and quality-gate settings are unchanged. The existing runtime regression and local Sonar evidence remains applicable.
