# System architecture

KISS-Chris-Stack is a local Codex plugin, not a web application. It has no frontend or backend of its own. The host loads skills/hooks and starts configured MCP services.

| Component | Responsibility and source |
| --- | --- |
| Package and marketplace | [.agents/plugins/marketplace.json](../.agents/plugins/marketplace.json) references this repository through `./`. The native [.codex-plugin/plugin.json](../.codex-plugin/plugin.json) declares skills, hooks, and the [onboarding dialogue](../skills/onboarding/SKILL.md): ask whether to set up a project, then require its explicit existing path on yes; no explains manual `/setup` or later automatic hooks. Root `plugin.json` contains only the identity to avoid the demonstrated portable hook-loading limitation. |
| Lifecycle | [hooks/hooks.json](../hooks/hooks.json) retains three stack and three original Ponytail handlers. [stack.js](../hooks/stack.js) prioritizes onboarding, then tells the active root to select the task route before setup/backfill. Tiny direct work skips preparation. Stack routes use root configuration as the sole initialization marker, supplying a read-only hook argv for strict default backfill before fresh runtime/MCP readiness. Delegated role context covers bounded direct work, stack phases and bootstrap roles without recursive setup/native goals. |
| Workflow | The [orchestrator](../skills/kiss-chris-stack/SKILL.md) follows [shared policy](../assets/global-stack-policy.md): tiny clear low-risk fixes delegate directly without stack overhead; clear normal features/bugs use stack with goal; unclear normal work uses [grill-with-docs](../skills/grill-with-docs/SKILL.md) before goal; large work uses [Wayfinder](../skills/wayfinder/SKILL.md) then all unblocked tickets concurrently through stack goals. Root delegates substantive work, retains native goals/approval relay and reviews evidence. All pure context collection always uses fresh `gpt-6-luna` low agents, facts-only referenced notes without implementation or design decisions. Root schedules separate RED/GREEN/evaluation phases per ticket within slots and isolated writes, verifies integrated source and uses explicitly textual/unregistered ticket goals under a native umbrella where the host supports only one active goal. Interviews wait for actual user answers and continue automatically once settled, without closing confirmation; `plan-mode=true` still yields for explicit goal approval. |
| Feedback memory | Project-local [`agent-traces/user-feedback/`](../agent-traces/user-feedback/README.md) retains actionable user feedback, scoped prevention actions and verification status. The root delegates prompt correction records, reviews relevant lessons before defining goals, and supplies them to the three roles as applicable acceptance checks. First-time and explicit setup create only the missing generic protocol and preserve existing records; selected stack tasks retain runtime-only setup. This is an agent workflow, not model training or an unattended recorder. See [learning workflow and example](LEARNING.md). |
| Evaluation | [evaluate](../skills/evaluate/SKILL.md) independently checks actual affected functionality and fresh configured gates. [evaluation-config.py](../scripts/evaluation-config.py) strictly validates independent `grill-with-docs`/`wayfinder` automatic-route booleans (default true), legacy `grill-me` (default true, explicit invocation only), `plan-mode` (default false) and live/SonarQube gates (default enabled). Explicit skill calls remain available when automatic switches are false; unresolved decisions remain blockers. See [configuration/evidence](EVALUATION.md). |
| Setup | The [setup skill](../skills/setup/SKILL.md) validates existing configuration, adds only missing current defaults through the resolver's explicit `--update` mode, preserves explicit values, and checks/repairs local prerequisites. First-time setup and explicit `/setup` fill documentation gaps. Missing root configuration is created only after successful runtime/session MCP and documentation checks; it is the sole initialization marker, independent of documentation contents. [setup-runtime.py](../scripts/setup-runtime.py) checks tools, pins, resource hashes, a real UIUX search, global rules, index, and MCP configuration. `--repair` uses pinned downloads and verifies RTK SHA256 before installation. |
| Wayfinder storage | `wayfinder-tracker` strictly selects local directory (default `.scratch`), explicit GitHub.com repository or GitLab HTTPS project URL. [setup-wayfinder.py](../scripts/setup-wayfinder.py) reuses the strict resolver and checks/prepares only the local root and owned `docs/agents/issue-tracker.md` block from existing provider templates. Pending first-init settings are validated via stdin before exact config-last marker creation; ordinary readiness reconciles only this binding. Unmanaged/unsafe/conflicting targets and failed hosted read-only preflights block without overwrite, remote inference or local fallback. Old ticket data remains intact. No CRUD engine or automatic provider login/install is introduced. See [operations](WAYFINDER.md). |
| Module documentation | After the system overview, [setup's module workflow](../skills/setup/SKILL.md#module-research-and-synthesis) maps every real module to allowed source paths and a documentation folder. One fresh-context `gpt-6-luna` researcher with reasoning `low` per module writes source-linked research notes only from that module. The root checks all notes and delegates synthesis of module architecture and usage documentation under `docs/<module>/`, linked from the overview. Existing layouts and completed work are reused; unavailable model/agent support or incomplete research blocks bootstrap completion. These researchers have no implementation goal and cannot edit source or delegate. |
| Project instructions | After documentation, [setup's final instruction phase](../skills/setup/SKILL.md#native-initialization-and-project-instructions) invokes host-native `/init` in the selected project; a delegated documentation role then optimizes `AGENTS.md` against actual evidence while retaining unique valid rules, managed blocks and instruction scopes. The root reviews preserved guidance and evidence. Canonical docs/traces are linked instead of duplicated. Native dispatch and review precede missing-marker creation and exact-file staging; unsupported dispatch remains pending for a manual native run. Ordinary readiness does not repeat this phase. |
| Readiness | The checker reports `runtime_ready`/exit code for executable checks. `ready=false` and `session_verification_required=true` prevent false session guarantees. Only an actual MCP status/context call in this session closes the gate. Missing tools require reload instead of a cached flag. |
| Setup Git handling | The [shared setup workflow](../skills/setup/SKILL.md#git-hygiene-and-staging) protects local artifacts through `.gitignore` before creation, then uses native Git to stage exact nonsecret setup files after successful first-time/explicit setup or authorized SonarQube setup. It preserves pre-existing index/worktree changes, reports mixed files left unstaged and skips staging outside Git. Ordinary readiness checks do not stage files. |
| Optional quality service | [setup-sonarqube](../skills/setup-sonarqube/SKILL.md) uses a bounded read-only Docker/Podman capability probe, then provisions only after consent. Project-local ignored `.env` holds credentials; nonsecret component configuration activates fresh analysis-specific gate checks before goal completion unless explicitly disabled through evaluation configuration. See [SonarQube operations](SONARQUBE.md). |
| Bundled skills | All skill entrypoints are directly under `skills/`. The Ponytail suite/hooks, Grilling, Caveman, UIUX code/data, and CodeGraph/RTK guides are included. Sources/licenses/modifications are recorded in [THIRD-PARTY.md](THIRD-PARTY.md); [bundle-manifest.json](../assets/bundle-manifest.json) records resource hashes. |
| Global rules | Setup updates only the stack marker block in global AGENTS.md and an existing AGENTS.override.md. PowerShell/shell marker helpers remain for existing consumers. There is no standalone installer. |
| Verification | [Contract checks](../tests/test_managed_configuration.py) and [lifecycle checks](../tests/test_plugin_lifecycle.py) verify resources, hook JSON, role separation, and negative readiness. Verifiers are thin invocations of the same checker. Actual plugin/hook discovery is additionally checked through Codex. |

Pins are in [versions.json](../assets/versions.json). The CodeGraph npm package and its observed runtime version are reported separately. Do not start parallel MCP processes, approve trust yourself, or overwrite unrelated MCP entries.

Decisions: [ADR 0001](adr/0001-dokumentation-und-agentenrollen.md), [ADR 0002](adr/0002-codex-marketplace-und-lifecycle.md), and [ADR 0003](adr/0003-documentation-language.md). Historical agent traces are retained. Complete installation from scratch on every platform and hook execution after user approval require separate verification.
