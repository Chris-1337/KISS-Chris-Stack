# Host and model observations

Use the [lifecycle matrix](LIFECYCLE.md#criterion-evidence-mapping) to bind each observation to its asserted behavior, current source, result and optional release boundary. A missing or empty filesystem assertion set fails; successful event execution alone cannot establish scenario success. Final current-source native observations and compatibility/usage summaries are retained under `.sonar-evidence/sdlc-t4/`; earlier target-specific receipts below remain historical. Missing usage is unknown, tokens/time are not currency cost, and savings require a comparable measured baseline.

The normal [CI workflow](../.github/workflows/tests.yml) defines the complete pytest suite on Windows and Linux with Python 3.13 and Node 24 for pull requests and pushes to every branch. It installs pytest through uv on clean runners and uses read-only repository permissions. It never invokes an authenticated model. Static workflow tests do not prove a hosted GitHub run has executed. Contributor, host and release verification use Python 3.13; plugin setup's baseline runtime is a separate prerequisite.

For explicit local model observations, run:

```powershell
uv run --python 3.13 python scripts/test-host-workflows.py --live --model gpt-6.1-sol --receipt .scratch/host-observations.json
```

Select an actually available model explicitly. Codex, Git, working normal authentication, and model access are prerequisites. The runner never substitutes another model. Each child invocation has a bounded timeout (`--timeout`, default 180 seconds); a failed prerequisite, malformed or incomplete event stream, nonzero exit, timeout, or filesystem assertion fails the command. Review the sanitized receipt to identify the failed stage. Model calls consume the account's normal allowance.

The runner uses disposable local projects and a disposable plugin profile. It stages allowlisted runtime resources, manifests and all 26 mandatory release resources from the trusted checker's authoritative `RELEASE_EXTRAS` contract before calling the local marketplace installer: the host installer copies ignored files, so installing the working tree directly would also copy protected files. Staging and fingerprinting exclude `.env*`, Git, scratch/evidence and cache directories, and reject symlinks/junctions. The complete release fingerprint must match the source after staging, installation and copying into the fixture. Runtime identity remains separately labeled as `candidate_fingerprint`; `release_candidate_fingerprint` binds the full artifact, including operative guidance.

The runner installs the staged candidate through the real CLI and verifies skill discovery through `codex debug prompt-input`. It copies the identical candidate into the standard project `.agents/skills` location, independently verifies that host's skill catalogue, and explicitly binds the original fixture prompt to that candidate's exact `SKILL.md` path before invoking authenticated `codex exec --json --ephemeral --ignore-user-config --model MODEL --sandbox workspace-write` sessions. This avoids a same-name user skill selecting another checkout. On Windows, the runner carries forward only an already configured `windows.sandbox` mode through `-c`; it does not initialize or change that mode. Inherited desktop IPC/thread identity and the desktop-only `CODEX_WINDOWS_REGISTERED_CORE` / `CODEX_WINDOWS_SANDBOX_PACKAGE_FAMILY` provider selectors are removed from the child environment. Parent settings, ordinary authentication, sandbox mode and trust remain unchanged. Installed-plugin discovery and authenticated project-skill behavior remain separate evidence layers; neither proves an authenticated installed-plugin session or automatic trusted hook execution.

The bounded [scenario catalogue](../tests/fixtures/host-workflows/scenarios.json) covers a tiny direct edit and an unanswered user decision. Exact file content and all other fixture files are independently checked; model success text cannot satisfy those assertions. A pending decision must preserve the complete project state. Actual delegation, researcher model/effort selection, native goals, separate stack roles, multi-turn interviews and parallel Wayfinder scheduling remain unverified unless supported by separate host evidence. A simple preserved-state observation does not prove those wider workflows.

Only sanitized JSON summaries persist: candidate/scenario fingerprints, CLI/Python/requested model identifiers, independent assertion results, elapsed time, and numeric usage fields actually present in host events. Absent usage stays absent, with its metric names recorded. Exec events do not independently identify the server model, costs or nested agent behavior. No cost estimate is invented. Child streams and debug prompt rendering stay in memory; raw model/tool transcripts, environment values and credentials are never saved by this runner. `--ephemeral` avoids normal Codex session-file persistence; ordinary host diagnostic/cache activity can still occur.

Normal project, sandbox and hook trust remain in force. The runner never supplies trust/bypass flags, copies authentication, edits the user's normal profile/cache configuration, or publishes anything. Untrusted hooks remain unverified. Disposable candidate files are removed after the run, including failures. Owned children and their tools are contained by a kill-on-close Windows Job Object or a POSIX process group; timeout cleanup terminates that owned group without targeting other sessions. Containment failure fails the invocation.

Historical Windows CLI 0.171.0-alpha.13 and Linux CLI 0.166.0 runs generated model events but failed the strict delegated-edit scenario. Linux passed the strict pending-decision observation; the historical Windows run stopped after the failed edit. Bounded diagnosis included a persistent-session probe, which also failed; ephemeral sessions alone do not explain those failures. A subsequent controlled Windows probe identified inherited desktop registered-runtime selectors as the immediate shell-provisioning blocker and exercised standalone child isolation plus exact candidate entrypoint selection. Current-source results require a fresh run of the implemented runner and its unchanged edit/pending-state assertions. Keep historical failures; a completed model turn, successful discovery or passing native desktop observation cannot establish successful CLI editing or independent delegation/model selection. Assess source identity, detailed results and cleanup from the corresponding receipts.

For a host that exposes native collaboration tools, a separate manual protocol can observe that target directly:

1. The independent evaluator prepares two disposable fixture directories, records exact initial bytes and allowed paths, and fingerprints the candidate policy/skill/runtime sources. When supplying a complete current candidate, stage the trusted runtime inventory plus every mandatory `RELEASE_EXTRAS` resource using [delivery's authoritative copy loop](DELIVERY.md#prepare-a-source-only-local-candidate), and independently require matching source/stage release fingerprints. Keep the narrower runtime and complete release fingerprints labeled separately. Root records the native host/session identity and the instruction sources supplied to the workers. Explicit instruction loading proves neither automatic plugin discovery nor trusted hook execution.
2. Root dispatches a real native direct worker for the bounded edit, with its fixture paths, intended result, unrelated-file preservation and focused verification. A separate worker receives the unanswered-decision fixture and must return the unresolved question without changing it. The evaluator prepares and judges fixtures; it does not implement the requested edit. Workers start no recursive groups, setup or native goals.
3. After actual tool completion, the evaluator independently reads and compares fixture contents: the edit must match exactly, every unrelated file must retain its bytes, and the pending-decision fixture must remain completely unchanged. Worker success text or an absence of reported writes cannot replace these assertions. Unexpected paths or state changes fail that observation.
4. Keep a sanitized receipt with candidate revision/dirty-source fingerprint, fixture hashes before/after, actual native dispatch/completion identifiers, observable requested/inherited model metadata, commands/assertions/results, elapsed time, evidence paths and owned-resource cleanup. Server model identity and usage remain unknown unless the host supplies them; do not copy raw conversation/tool transcripts. Rerun affected observations if candidate sources change.

This protocol proves only the observed native dispatch and fixture behavior with supplied current instructions. CLI installed-candidate discovery, authenticated project-skill execution, native-host behavior and automatic installed-plugin hooks are separate evidence layers. Record each target as passed, failed or unverified from its own assertions. This manual protocol adds a supported-host observation; it does not relax the CLI runner, excuse a failed required gate or certify stack roles, research dispatch, native goals, multi-turn interviews or parallel Wayfinder scheduling.

The parser and subprocess tests use synthetic events only to prove failure handling and summary contracts. They are not live model evidence. A successful observation describes the selected CLI/model invocation and candidate fingerprint; it cannot guarantee future host/model compliance.
